# Guided token-count preview

Use this path when someone wants to understand **their own counts** without installing Tokenpull or publishing. It is an unverified, user-supplied preview, not a measured SignalAF profile. The plugin does not scan logs, read ChatGPT/Codex account usage, or submit a score. Never call the shared submission MCP for this task.

1. Ask which platform and period the counts cover. Guide the person to that platform's usage dashboard, export, or the existing Tokenpull output. Request only four aggregate numbers when available: fresh input **I**, output **O**, cache-write **W**, cache-read **R**. Do not ask for raw session JSON, full logs, prompt text, credentials, or a chat transcript. If a source's `input_tokens` includes cached tokens or is cumulative, resolve that source's semantics before mapping it to I; never double-count cached input or add cumulative totals as turns.
2. State exactly which pillars are observed, missing, or reported zero. Do not convert a missing W or R to zero. For positive I, calculate Leverage = R/I when R is known, Velocity = O/I when O is known, and Yield = R×O/I² only when I/O/R are known. Construction = W/R only when both are known and R is positive. If I is zero or the denominator is otherwise invalid, leave the affected metric unavailable. Show the input values and formula so arithmetic can be checked. Use the canonical TTEOP policy for any additional metric; do not improvise a class, archetype, percentile, or verification label.
3. If the user wants a deterministic full preview, direct them to the existing [SignalAF paste preview](https://signalaf.com/score/paste), which posts the entered counts to SignalAF for calculation but does not publish a board entry. The [Yield calculator](https://signalaf.com/tools/yield-calculator) computes the basic Yield formula in the browser. Be clear which path sends counts to SignalAF. The separate SigRank MCP's `rank_paste` is an implementation reference, not a tool to route through this isolated plugin.
4. For “where would I stand?”, explicitly fetch the **Active / Total / All-time** displayed board with `get_leaderboard(window="all", view="total", limit=100)` unless the user names another window. Confirm the returned `total_eligible`, access cap, scope, as-of state, and that all comparison rows needed for the statement were fetched. If the list is complete, an arithmetic insertion into the displayed Yield ordering may be described as a **hypothetical displayed position** with the tie rule shown. Missing actual window bounds and verification evidence mean this is only an illustration against displayed numbers, not an aligned measurement comparison. Never call it a published rank, percentile, verified placement, or eligibility decision. If the list is capped or contains missing Yield, give only a side-by-side illustration and say a position cannot be established.
5. Keep **Active** and **SigArena's mixed historical board** separate. The public plugin tools expose the claimed Total board and a broader By-platform view; unclaimed does not prove seeded origin. SigArena's `/all-time` page describes seeded and live profiles together, and its separate MCP has no seeded-only tool. Do not silently treat the broader view, old mock fixtures, or SigArena's mixed board as a seed-only cohort. A seed-only comparison needs a dated dataset with explicit per-row origin and a verified source.

Close with the practical distinction: this preview can explain a token-flow pattern and an illustrative position, while Tokenpull measurement and SignalAF publication remain separate steps. No automatic submission follows from a paste.
