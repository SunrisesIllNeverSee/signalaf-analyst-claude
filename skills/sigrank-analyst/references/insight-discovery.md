# Discover what a SigRank board shows

Before answering, inspect the returned board as a whole. This is a **silent comparison pass**, not a response template and not a request to promote a particular operator. Let the user's question determine the subject; let the observed values determine which relationships are noteworthy.

- **Scope and distribution:** Identify the window, view, population size, and the range and center of available metrics. A value is unusual only relative to a named, compatible comparison set. Avoid treating the current #1 as the default reference for every other row.
- **Scale versus structure:** Compare total I/O/W/R volume with Yield, Leverage, Velocity, and operating ratio. Look for rank reversals, similar totals with different shapes, or similar Yield reached through different reuse/output mixes. Total tokens are `I + O + W + R` only when all four pillars are observed. If a response is capped, derive volume order only among returned complete rows, not as a board-wide rank.
- **Mechanism:** Use exact returned pillars to explain a finding. `R/I : 1 : O/I` is the cache-read : fresh-input : output operating ratio; `Yield = (R/I) × (O/I)`. The site's Eff metric, when relevant, is `(R + W + O)/(4I)` for positive I and complete pillars. Compute derived values from exact counts, not abbreviated K/M/B display figures. A small I can make ratios extreme; note that only when it materially changes the interpretation.
- **Other dimensions:** If a reliable source supplies categories such as platform or operating mode, compare within and across those categories when relevant. Do not infer a person's identity, account operation mode, or work quality from a handle, rank, or token pattern. A user-provided category applies to that conversation unless separately published by SignalAF.

Choose the one or two relationships that best answer the user, based on size of the contrast, distinctiveness within the stated cohort, explanatory value, and source reliability. Equally valid boards can yield different lead findings for different questions. Do not encode a favored profile, fixed conclusion, or mandatory “surprise.” A straightforward board request may simply need the leaders and one crisp observation. Keep missing metadata in a short relevant note or maintainer report; it should not overshadow a supported result.
