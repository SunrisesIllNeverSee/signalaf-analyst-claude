# Teach Build Archetypes

Start with the pattern in the operator's observed numbers and explain why its label fits. A Build Archetype describes operating shape for the selected snapshot; class describes qualification/scale, workflow mode describes execution arrangement, and rank describes field position. None substitutes for the others.

Use the [detailed Build Archetypes wiki](https://signalaf.com/wiki#archetypes) for definitions. The [Human in the Loop Is Unmeasured article](https://signalaf.com/blog/the-human-in-the-loop-is-unmeasured) connects the ten shapes to the research field; the [SigRank dashboards](https://signalaf.com/blog/sigrank-dashboards) provide composition and distribution illustrations. Read the relevant article when asked for its reasoning; use its dated cohort for context, not today's rank or prevalence.

| Family | Archetypes | Useful reading of the operating pattern |
|---|---|---|
| Reuse depth | Input-bound, Priming, Contextual, Deep Reader, Archivist | Increasing cache reuse relative to fresh input with comparatively little cache construction. |
| Active construction | Builder, Recursive, Amplifier | Cache writing accompanies reuse; the label distinguishes the reuse depth within that construction branch. |
| Generation | Kinetic | Output relative to fresh input crosses the classifier's generation threshold. |
| Convergence | Convergent | Reuse, generation and construction all cross the classifier's calibrated thresholds; this branch takes precedence. |

Prefer returned `archetype_details`: canonical key/name, family, explanation, axes and classifier version. The website and analyst service reuse the current app classifier, identified as `signalaf/build-archetypes` version `1.0.0` in the pending website release. That identity pins existing rules; it is not a new metric or a TTEOP base field. Follow the actual returned version instead of assuming the release has deployed.

Complete nonnegative observed I/O/W/R and positive I/R are needed. Zero cache creation is valid; missing cache creation is unknown. A null label means classification is unavailable, not that the operator has no operating pattern. On an older server, explain a fully supported local calculation as derived under packaged rules. Do not promise a manually stored profile label.

When useful, compare the defining axes with a peer or matching field quartiles: a Kinetic profile can have high generation and low Construction; a construction-family profile may stand out for context creation rather than the highest Yield. Use actual values and do not invent an outlier or human/agent classification. Archetypes are operating patterns, not personality or work-quality judgments.
