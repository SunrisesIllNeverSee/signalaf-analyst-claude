# Read the SignalAF board and field

A placement needs a **window, view, category, population, and sort metric**. The isolated SigRank | SignalAF MCP exposes `get_leaderboard` for `7d`, `30d`, `90d`, and `all` (all time). Its default is the website's **Total / All** selection of claimed operators sorted by published Yield. `view="platforms"` selects the broader **By platform / All** public selection; it can include unclaimed rows. A platform filter also selects that view. The response states `scope.view`, `scope.category`, `scope.population`, `sort_metric`, `board_url`, `total_eligible`, and per-row provenance. State those values when reporting ranks. Category `Operator` and `+ Outliers` are website controls, not supported tool scopes; inspect the rendered board when the user explicitly asks for them and do not relabel a tool result.

For an unspecified overview, make **one explicit `window="all", view="total", limit=100` call** and label it Active / Total / All-time; do not rely on the MCP's 30-day default. This is a plugin presentation default, not a change to the website or MCP contract. Keep 7d/30d/90d available on request. Do not combine windows into a synthetic snapshot.

Present a successful board call as a leaderboard, not a data-quality audit. Show every returned operator in rank order in a compact table with the requested metrics and operating ratio first; shorten the board only for an explicit top-N request, then one energetic but factual “what stands out” sentence about reuse, generation, construction, or the operating ratio. Give the live board link. A compact closing note may distinguish the published board from missing per-row measurement-class detail when relevant; do not repeat the tool's provenance warning as the headline. The published placement is valid within the returned board scope. Do not make the reader pass a verification checklist before seeing it.

For live rankings, call `get_leaderboard` with the requested window before answering or browsing. For a four-window overview, make four calls; do not reuse one window's rows for another. If a call fails, show its error and leave that window unverified. Do not use the old shared `/api/mcp`, `rank_windows`, a homepage example, search snippet, cached table, or a calculated rank as a substitute. If asked to list plugin tools, enumerate the five exposed names without running them merely to provide a list.

The leaderboard returns the app's published Yield, Velocity, Leverage, SNR, Construction, 10xDEV, Scale V, I/O/W/R pillars, and `operating_ratio` where present. Read [insight discovery](insight-discovery.md) to examine the relationship between fresh input and the system-side token flow before selecting an answer's angle. In a board explanation, give the operating ratio prominence when it is the revealing fact: `cache-read : fresh-input : output`, normalized to one unit of fresh input. Its first and last parts summarize Leverage and Velocity; cache writing is a separate pillar. Report only non-null values. Null is unknown, not zero. Never calculate Velocity from rounded Yield and Leverage or use rounded ratio text for exact arithmetic. For broader field context call `get_field_stats`; it defaults to the public By platform / All population, which can include unclaimed rows. Pass `view="total"` when comparing its distribution with a Total board. Keep different populations separate. `measurement_class_counts.Unknown` counts board rows whose exact-versus-reconstructed evidence class is not published; it is not an Unverified count.

Do not label an unclaimed operator as *seeded* unless source provenance confirms that origin. The current public records do not preserve that provenance reliably. A display-name fallback may use codename without changing identity. `get_operator` returns an existing public profile by codename, including a public codename supplied by the user. `compare_operators` compares two values from the same selected board scope and returns their displayed metric deltas. If snapshot observation dates differ, describe the delta as a difference between the published board snapshots, not equal-duration activity.

The Active board is the claimed-operator Total view. [SigArena's all-time board](https://sigeconomy.com/all-time) is a separate, larger historical surface whose own page describes a **mix of seeded and live profiles**. It is not a seed-only cohort and is not the plugin's By-platform view. SigArena has a separate eight-tool read-only MCP at `https://sigeconomy.com/api/mcp`, but those tools fetch SignalAF's public API and do not expose a seeded-only leaderboard or per-row seed-origin proof. Do not connect that MCP to this isolated V1 plugin or merge its ranks with the Active board. The SigArena domain failed DNS from the October 2026 workspace check, so a live response was not verified here; if the user asks for that website's current placements, inspect the actual page/tool response and report its as-of state.

`total_eligible` counts measured, ranked operators in the returned board scope; the response may still be capped by `limit`. Check `returned_count` against `total_eligible`. A result with `gated=true` can mean the caller requested fewer rows; it does not by itself establish a paywall or account access restriction. The current tool accepts up to 100 rows; if more exist and no cursor is returned, label the displayed portion accurately and link the full website board. Do not silently omit returned rows or claim to have fetched the whole board when counts differ. An operator row has `provenance.ranking_eligible=true` when it belongs to that published ranking. This flag describes **board inclusion**. The website board does not publish a per-row verification state or exact-versus-reconstructed class, so the plugin returns `null` for those fields and does not independently inspect signed uploads. The response envelope is not an operator and can have `ranking_eligible=false`. Report ranks as published placements, never as verified Exact-4 measurements. Mention unpublished evidence class only if the user asks or a specific interpretation depends on it. If an older host still returns `ranking_eligible=false` on a ranked row, state the contract mismatch rather than declaring the displayed rank invalid.

The board page may use an ISR-cached initial Total table while the API-backed platform view reads a fresher selection. If exact website placements are requested, inspect the rendered view and its as-of state. Report a mismatch explicitly instead of deciding one is the other. Ratios with a tiny fresh-input denominator require a sensitivity caveat; neither rank nor ratio measures intelligence, productivity, personality, or work quality.
