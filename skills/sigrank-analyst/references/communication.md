# Communicate a supported SigRank finding

For a board or profile answer, open with the published result and one evidence-backed structural finding. Name the period and population naturally. Derive the finding from authoritative I/O/W/R and returned ratios: which of reuse (R/I), generation (O/I), and construction (W/R) is actually distinctive? If a matching field view exists, state its sample size. A small field or missing exact window bounds is limited context, not proof of a statistical outlier. If no field view exists, omit invented percentiles. Keep any material scope note short and after the interesting finding. Preserve the same factual scope across every format below. Once the measurement boundary is established, keep it implicit in subsequent answers unless a new claim could mislead; do not make every answer or share draft end in the same disclaimer. Missing verification metadata belongs in a response only when relevant to the question.

| Format | What to deliver |
|---|---|
| Plain English | The live result, one concrete relationship in familiar words, why it stands out, and a brief note only if needed. Translate cache reads as earlier context reused by the system. |
| Technical | I/O/W/R values and units, decisive ratios and formula, scope/provenance, and any denominator or missing-data caveat. |
| What is unusual? | The strongest contrast between axes or against a compatible field distribution; distinguish an actual outlier from a merely large token total. If nothing is unusual, say that. |
| LinkedIn | Two or three short sentences with one structural insight and a profile/board link. No claim of productivity, intelligence, or work quality. |
| X | Label the draft as an X post. Keep it under 280 characters, preserving the same observation and link where it fits. Never imply a verified rank from synthetic or pasted counts. |
| Share-card copy | A short headline and one supporting line rooted in a returned metric/ratio. Link to an existing SignalAF profile/card if available; do not invent a badge, image, verification seal, or publish a new card. |

When a source returns a canonical `share_url`, use it. Existing site surfaces include `/user/{codename}`, `/compare` and `/share/mcp`. Drafting copy is allowed; publishing content or creating a profile is a separate action. If the finding is based on unverified, pasted, or synthetic data, label that origin in external-facing copy. Never turn an archetype into a personality label.
