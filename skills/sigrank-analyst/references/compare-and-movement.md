# Compare operators and read movement

Compare the same metric definitions across compatible windows and evidence coverage. Start with the focal operator's published position and strongest supported structural contrast; put alignment limits afterward in one short note. Compare the *drivers* of the shape: whether Leverage, Velocity or both account for Yield; whether W/R distinguishes active construction from passive reuse; whether input volume is changing the denominator. A higher rank or metric does not establish a better person or better work.

Make the **first operator named by the user the focal person**. If the request is “top two,” resolve the current board rows first: the displayed #1 is A and #2 is B, using their returned **codenames** for tool calls even when their display names differ. Explain A's token-flow structure, then use B to reveal what is distinctive about A; do not alternate between two equal mini-biographies. For an open-ended comparison, choose varied, relevant lenses rather than only the nearest rank: A versus one contrasting operator if requested or supported, A versus the matching Active field distribution, and, only when useful, A versus the separately sourced Four Degrees reference ladder (signalaf.com/wiki/four-degrees). Vary the informative dimension (reuse, generation, construction, input denominator, or volume) instead of repeating Yield rank. Do not invent a comparator or silently pick one.

For two operators, state the selected window, view and field population. Call `get_field_stats` with the **same** window and `view="total"` for a Total-board operator; use its median and quartiles to contextualize A. Each median is calculated per metric and is not a single “median operator” profile or an operating ratio unless the source provides one. `compare_operators` returns numeric differences between the two published values in the selected board scope. If observation dates differ, make clear that those differences are a current-board contrast, not equal-duration activity or evidence of better work. If `comparable=false`, present the snapshots separately and quote the reason. If either profile lacks W or R, do not classify construction on that side.

The Four Degrees ladder lives on the [Four Degrees of Leverage wiki page](https://signalaf.com/wiki/four-degrees) (the stable reference; the live site design may also show the chart on the homepage). It teaches: static modeled AA baseline, Operator Center of Mass median, power-user/top-100 median, and top evaluation. Use it as a **separate explanatory reference** when the user wants broader context. Name each column's definition, source and as-of state; medians are not arithmetic means, and the site's broader/seeded population is not automatically the plugin's 22-person Active / Total cohort. Its figures can change or be cached. Never describe its top-100 median as a statistic of an Active board with fewer than 100 operators or claim that a site value is the current MCP field median. The direct Active comparator is `get_field_stats` for the matching scope. If the live Four Degrees chart includes raw telemetry averages, distinguish its arithmetic-mean counts from median metrics and cite the displayed group sizes and dates. Do not form a fictitious median operator by combining independently calculated medians or means.

The site headline median and Four Degrees Operator Center of Mass use the same all-time real-operator Yield median. Check the live rendered values and update date before quoting them. This broader cohort is still separate from the plugin’s claimed-only Active / Total board; use matching MCP field stats for a focal Active operator. The site’s `top_yield` comes from latest 30-day system-stat snapshots, while the chart’s top evaluation is all-time, so label those scopes separately. The aggregate API has an all-time yieldable-snapshot median, a different cohort from the site operator median. Do not invent a reconciliation or average across cohorts.

For two complete historical pillar windows, compute exact deltas through canonical code. Mention divergence when, for example, R/I rises while W/R falls. Do not infer why the change occurred without independent evidence.

The public SignalAF history endpoint currently exposes retired SIGNA-RATE plus rank and class tier, but no complete historical I/O/W/R or Yield. Do not route V1 movement through this retired metric. A live-public movement answer should say that canonical movement is unavailable unless a separate validated, window-aligned source supplies pillars and metrics. The internal app query already calculates Yield from stored snapshot pillars, but drops it from this public response. The smallest upstream addition is a versioned historical four-pillar snapshot with window boundaries and provenance, or a canonical Yield series whose source windows are explicit. Do not infer movement in Leverage, Velocity, construction or Build Archetype from Yield alone.
